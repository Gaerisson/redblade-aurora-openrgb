# Color Lab design and implementation plan

**Goal:** Extend the existing single-profile Studio with a visual color editor, selection gradients and configurable reactive lighting, keeping RedBlade branding and keyboard input timing.

**Architecture:** Keep local WebView2 and typed C# bridge. Apply batch per-key colors atomically with bounded undo/redo. PC effects use OpenRGB and a bounded, in-memory, device-filtered Raw Input event source while an effect is running. Full firmware adds compact last-key ripple/wave styles for autonomous fallback lighting.

**Decisions:** Extend existing code, rather than add a second editor or plugin engine. Persistent per-key HSV colors and firmware reactive settings coexist with host-only effects; Aurora retains normal priority outside an explicit Studio effect session. User delegated routine design decisions and requested execution, so no additional design-approval gate.

**Editor:** Click, Ctrl-click, drag paint selection and box selection; add/subtract mode; presets for all, letters, gaming, numpad and media. Solid, linear and radial gradients over the selected geometry, editable colors/angle, palette swatches, undo/redo. Clicking a key loads its color. Single profile, EN/FR, responsive editor.

**PC effects:** Existing six presets plus spectrum, twinkle and reactive. Direction/angle, scale, reverse, up to eight palette colors, background and selected key zones. Optional reactive overlay with key fade, ripple or row wave; color, duration, width and opacity. Raw Input receives only scan codes from keyboard VID320F/PID5136; bounded transient events, no text/keystroke log or storage. Hidden input message thread lives only during an effect session. Existing pause/restore and SDK detection safeguards remain.

**Firmware:** Profile byte10 ReactiveStyle:0 legacy key fade,1 ripple,2 horizontal wave. Byte11 ReactiveWidth:0 default16 geometry units,4..64 explicit. Existing modulebit3 enables reaction; effect slot1 holds peak HSV; TrailFrames1..15 holds duration. Styles affect only fallback/local white, retaining host priority. New press restarts the single autonomous wave, bounding work and memory. Bytes12..15/415 remain zero. Protocol1696/416 unchanged; firmware style settings requireFull0.11. Full/Core0.11 with both BINs/sources eventually published; no automatic physical flash.

**Contracts:** `setKeyColors {colors:[{led:int,color:#RRGGBB}]}` 1..109 unique indices, validated before any mutation. `undo`/`redo` restore complete active-profile edits with bounded history. Snapshot `editor {canUndo,canRedo}`; profile adds `reactiveStyle`, `reactiveWidth`; capability adds `reactiveStyles`.
`EffectSettings` keeps existing five ctor fields. Optional init props: Angle0..359=0,Scale25..400=100,Reverse=false,Palette=[](0 or2..8hex),TargetLeds=null(all) or1..109unique,Background=#000000,ReactiveEnabled=false,ReactiveStyle=key|ripple|row,ReactiveColor=#FF274E,ReactiveDurationMs100..2000=700,ReactiveWidth1..8=2,ReactiveOpacity0..100=100. Defaults preserve existing requests/imports. Native bridge accepts the same camelCase fields. Frontend preview tracks those settings and simulates key events for preview only.

**Invariants:** Full usable SRAM>=64 measured by heap symbols; stacks768+1536/Recorder192/timer720896Hz/USB1ms/8LED33ms unchanged. No arbitrary imported scripts or untrusted URLs. Bound batches, history, palettes, events and all numeric values. Keep user profiles/VIA/macros. Do not replace published0.10 assets.
